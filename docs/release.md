# アプリの公開と更新

サイクルガイドを Google Play に出すときの流れと受け持ち。SanpoGuide の[公開と更新](https://github.com/duwenji/yorisoi-sanpoguide/blob/main/docs/release.md)と同じ形で進め、Play の操作は SanpoGuide と同じ Google Play Developer API（サービス アカウント）を使う。

## 方針

- 最初は**内部テスト**まで出す。内部テストは、製品版の前に要るクローズドテスト（個人のデベロッパー アカウントは 12 人以上・14 日以上。要件 R-5）を待たずに出せる
- クローズドテストと製品版は、内部テストで確かめてから進める
- アプリ名は「サイクルガイド」、運営者・問い合わせ先は SanpoGuide と同じ

## 受け持ち

| 誰が | 何を |
|---|---|
| 開発者（Play Console の画面） | アプリを作る（API では作れない。有料として作った）。サービス アカウントにこのアプリの権限を付ける。内部テストのテスターを登録する。API で入れられない申告（アプリのアクセス権・広告・コンテンツのレーティング・対象年齢・フォアグラウンドサービスなど） |
| Claude | アップロード鍵とリリースの署名の設定、署名済みの AAB、プライバシーポリシー（GitHub Pages）、データ セーフティの答え（CSV）、ストアの説明文・スクリーンショット・アイコン・フィーチャー グラフィック、フォアグラウンドサービスの申告の動画、`tools/play.mjs` での内部テストへのアップロードと掲載情報・データ セーフティの登録 |

## 流れ

1. アップロード鍵を作り、`keystore.properties` で署名する（鍵とパスワードは Git に入れず、別の場所にも写しを置く。なくすと同じアプリとして更新できない）
2. プライバシーポリシーを GitHub Pages に出す（位置の権限を使うアプリは必須）
3. 開発者が Play Console でアプリを作り、サービス アカウントに権限を付ける
4. ストアの掲載情報・データ セーフティを API で入れ、残りの申告を開発者が画面で入れる
5. `./gradlew bundleRelease` で AAB を作り、エミュレータでリリース版を確かめてから、内部テストに上げて審査に出す
6. 新しいアプリでは、アプリの審査を通るまで、内部テストのテスターには仮のアプリ名（パッケージ名と「unreviewed」）で見える。審査の結果は [公開の概要] で確かめる。審査を通るまでクローズドテスト（alpha）には出せない（API が「draft app」として断る）
7. テスターは参加用 URL をブラウザで開き、テスターとして登録した Google アカウントで参加する。端末に複数のアカウントがあると、Play ストアが別のアカウントで開いて黒い画面のまま止まることがある。Play ストアの右上でアカウントを切り替える

## プロンプト・パックの公開

チャンネル管理システムの審査（`cycle` のチャンネルの見本、X-6）は、このアプリが送るのと同じプロンプトを使うため、`:prompts` を GitHub Packages に公開する（`io.github.duwenji.yorisoi.cycleguide:prompts`、要件 F-30）。プロンプト・組み込みのチャンネル・審査の見本（`ReviewSamples`）を変えたら、`gradle.properties` の `cycleguidePromptsVersion` を上げ、main に入れてからタグ `prompts-v<版>` を push する（`.github/workflows/publish.yml`。タグと版が違うと止まる）。使う yorisoi の版は先に公開しておく。
